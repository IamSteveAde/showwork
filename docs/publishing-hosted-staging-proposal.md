# Isolated hosted staging proposal — approval required

Production remains NO-GO. This is a deployment proposal, not a deployed environment or evidence of hosted performance. No production credentials or live publishing changes are required. Scope is the portable publishing candidate, synthetic records and mocked social APIs only.

## Proposed hosting configuration

Use a new dedicated Netlify project `showwork-publishing-lab-<run-id>` with a standalone artifact, no Git auto-deploy and no connection to the Showwork site. Prefer a separate billing team/account so test usage cannot pause the production team's sites. Do not migrate the existing account's billing plan. No Next.js application, production cron files, custom domain, billing, email or inbox jobs are included.

Functions: one every-minute scheduled admission/wake handler; one authenticated background consumer; one authenticated fixed-shape wake ingress if authentication before background enqueue is required. Scheduled admission budget remains 15 seconds, with a 25-second total internal deadline. Consumers run at most ten minutes, stop admitting work before shutdown, and preserve durable recovery. Netlify limits remain 30 seconds scheduled and 15 minutes background; those limits do not establish that our code meets them. Actual runtime/memory availability must be checked before creating the project. Propose 2 GB per consumer for the cost envelope, Node runtime compatible with the tested Node 22 code, two leased consumers, eight account-aware attempt slots each and three heavy transaction slots globally.

Database: a fresh synthetic PostgreSQL 17.6 instance plus PgBouncer 1.26 in transaction mode, one database/user mapping, `default_pool_size=5`, `reserve_pool_size=0`, `max_db_connections=5`, `max_user_connections=5`. Database role connection limit also five. No application route to direct PostgreSQL; only the pooler is exposed with verified TLS. Provisioning credentials remain with the operator, never in Netlify. Monitoring must include application backends, not confuse observer/admin connections with application use. A private PostgreSQL+pooler container host is proposed; provider, exact region and hourly quote remain to be selected before deployment approval is executable. No use of the unconfigured InterServer VPS is assumed.

Choose the available Netlify region nearest the isolated database initially; record both actual regions. A second deliberately distant configuration may measure sensitivity, but requires its own reviewed configuration. Changing this staging project's region must not alter production functions. The five-backend cap is enforced centrally, not five connections per invocation.

Use the existing native publishing integration with fail-closed mock transports. Mock responses/attempt ledgers must survive consumer termination using the isolated database; process-local mock counters alone cannot prove cross-process duplicate prevention. Synthetic media comes from a fixed staging origin with no user-selected URLs. No real social access tokens exist in the environment.

## Security boundaries and activation gates

- Standalone build manifest allowlists candidate modules, synthetic fixtures and mock transports. Exclude `.env*`, production site metadata, real provider transports and deployment credentials. Scan the final bundle and enumerate function names before upload.
- Project-bound staging database identity and expected database marker are checked on startup. Reject any other host/database, absent marker, expired run or non-staging environment. The database login has only required DML on synthetic tables, no DDL/role creation/superuser privileges and no access to other databases. Audit PUBLIC/inherited grants before activating it.
- Strict certificate validation with the hosting provider's verified CA. No `rejectUnauthorized=false` or permissive TLS fallbacks. Explicit statement/lock/transaction timeouts; 2-second statement timeout initially matches the local test.
- Wake ingress accepts only bounded generation hints (512 bytes), HMAC over method/path/body/timestamp/nonce, 30-second timestamp skew, durable nonce uniqueness and project/run identity. Limit authenticated wake ingress to ten requests/minute; separately exercise a bounded overlap test. Consumers additionally require a valid durable consumer lease. Never accept SQL, media URL, provider endpoint, connection string or post payload from callers.
- Run expires six hours after explicit activation; expiry and emergency-disable checked on tick, lease renewal and before provider operations. Database credential expiry is independent of application checks. External cleanup watchdog disables the schedule and revokes credentials even if the project stops responding.
- Egress is allowlisted to the synthetic pooler, fixed synthetic-media origin and staging wake endpoint. Application-level URL allowlisting is not network isolation. Verify available hosting network restrictions; if platform-level restrictions are unavailable, report that limitation and require approval of the residual boundary before activation. No claim of verified egress isolation is made yet.
- Log only synthetic job/run IDs, durations, SQL error codes and state transitions; never connection strings, tokens or content. Fault injection is selected from fixed cases in an operator-signed run manifest and unavailable on unrestricted public routes.

## Hosted test sequence and evidence

1. Before any workload: verify project identity, permissions, TLS, expiry, egress, mock-only build and five-backend cap. Record immutable build/source hashes, runtime/memory, database/pooler settings and billing allowance.
2. Measure connection/TLS establishment separately from warm checkout, fixed query execution, transaction begin/commit and coordination calls. No injected latency in the actual-host measurement arm. Report p50/p95/max and sample counts. Repeat with explicit 320/1,380 ms injected coordination as a separately labeled comparison, never confuse injection with network measurements.
3. Collect fresh-runtime IDs and module initialization timing for at least 20 observed new instances plus 100 warm calls. Do not assume an idle interval guarantees a cold start. Capture actual cron scheduled timestamps, function entry, wake request, durable acknowledgement and consumer start across at least 30 ticks, including posts just after a tick.
4. Repeat 5/50/250 workloads at least three times, distributed and shared accounts. Record each attempt start and confirmation, account/platform maxima, SQL counts/errors, native failures and durable mock operation ledger. Compare with the local 39.19/42.39-second and 195.15/221.26-second maxima. A mock acceptance is not a confirmed publication.
5. Send bounded overlapping schedule/wake calls; sample PgBouncer pools and pg_stat_activity, record global slot/lease peaks. Accept only <=5 application backends, <=3 heavy operations and <=2 leased consumers. Include sustained five-platform arrivals and stale epochs, not only finite bursts.
6. Force process termination at pre-send, after mock acceptance, after proof commit and during finalization. Test lost wake responses/delivery, timeout/disconnect, lease renewal failure and expiry. Rotate consumers at ten minutes during the complete 250-post lifecycle. Reconcile uncertainty through status-only lookup or quarantine, never automatic republish.
7. Measure graceful shutdown and hard termination separately. All admitted jobs must reach confirmed, explicit failure or observable quarantine; no silent disappearance, duplicate publishing or bypassed permission/token/cancellation fences.
8. Publish the measured evidence and GO/NO-GO assessment. Speed targets must include cold/wake/cron delay. Zero duplicates and zero lost jobs are mandatory. Hosting must retain runtime margin; do not use a 120.30-second result as a pass for a 120-second target.

## Rollback and cleanup

Disable new work and ingress first; preserve/export synthetic queue and mock ledger evidence. Allow bounded graceful drain, then revoke database/wake credentials and terminate remaining sessions. Remove scheduled registration/project, database/container and synthetic media; delete temporary secrets and local deployment metadata. Verify the old URLs reject requests, no scheduled invocations continue, database sessions are gone and billing resources are deleted. Retain only redacted reports/source hashes for review. An independent operator/watchdog must be able to revoke the staging role without cooperation from Netlify. Rollback never touches production.
