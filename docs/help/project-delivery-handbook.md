# Showwork Project Delivery handbook

Reviewed: 27 October 2026.

Web version: `/help/project-delivery`. Guides describe the implemented interface; options depend on your role, plan and connected-platform permissions. This document does not certify live provider integrations.

## Getting started

Choose a delivery workflow and set up the project.

### Choose direct delivery or a managed project

Start with the workflow that matches the stage of your work.

Guide: /help/project-delivery?guide=choose-delivery

**Before you begin:** A signed-in creator with available project access.

1. Use a direct delivery project when files are already prepared and you want to organize, share and review them with a client.
2. Use a managed project when you need to define a brief, assign tasks and review team uploads before releasing finished files.
3. For direct delivery, open the new-project flow from your delivery dashboard.
4. For managed work, open the managed-project creation flow and begin with the brief.
5. Keep the client-review portal separate from your creator dashboard; share the intended client link rather than an internal dashboard address.

**What happens next:** You start the appropriate workflow without treating internal task uploads as finished client deliverables.

**Good to know:** Publishing to a delivery client is not publishing to Instagram, TikTok or another social network. Social publishing belongs to the Marketing Workspace.

Related: Create a direct delivery project; Create a managed project and its brief; Share the client delivery portal.

### Create a direct delivery project

Give a client a dedicated place to review your finished work.

Guide: /help/project-delivery?guide=create-delivery

**Before you begin:** A signed-in creator with available delivery/project allowance.

1. Open your delivery dashboard and start a new project.
2. Enter the client name and choose the client access code. Use Suggest if you want a generated code.
3. Add a delivery tagline and any available presentation settings.
4. Build the sections for your images, videos or documents and select the files to include.
5. Save each prepared section, check the file list and submit the project.
6. Wait for creation and uploads to finish, then open the project dashboard and check Work before sharing.

**What happens next:** The delivery project is saved and its completed files appear in the creator dashboard.

**Good to know:** Keep the creation page open while uploading. If a transfer fails, inspect the existing project before starting another one.

Related: Organize delivery files into sections; Add more files to an existing delivery; Share the client delivery portal; Recover from a failed upload or confirmation.

### Navigate your delivery dashboard

Know where to find files, access details, collaborators and activity.

Guide: /help/project-delivery?guide=navigate-delivery

**Before you begin:** The project owner; collaborators use the project views available to them.

1. Open the project from your delivery dashboard.
2. Use Overview to inspect file counts, approval progress and delivery/payment state.
3. Open Work to inspect files, add content and handle revisions.
4. Use Client access for the portal link and access code, Team for collaborators, and Activity for recorded client visits.
5. On smaller screens, use the project navigation controls rather than looking for a desktop sidebar.

**What happens next:** You can find the right project controls without confusing the creator dashboard with the client portal.

Related: Share the client delivery portal; Read approval progress and delivery health; Inspect client visits and delivery activity.

## Uploads & files

Add, replace and organize the work you deliver.

### Add more files to an existing delivery

Extend a project without rebuilding its delivery page.

Guide: /help/project-delivery?guide=upload-files

**Before you begin:** The owner or an authorized uploader, with storage and upload allowance available.

1. Open the project dashboard and select Work.
2. Choose Add more files.
3. Select Images, Videos or Documents and fill in the requested section information.
4. Choose the files from your device and review the selection before uploading.
5. Start the upload, follow its progress and wait for completion.
6. Check the resulting files in Work and preview the client portal before telling the client that new content is ready.

**What happens next:** Completed uploads are registered in the intended project location.

**Good to know:** Upload allowances depend on your plan and project. A transferred file may still be awaiting final registration; do not assume a failed confirmation means the entire transfer must be repeated.

Related: Organize delivery files into sections; Recover from a failed upload or confirmation; Pause an upload and continue safely; Choose the right media type and file format.

### Choose the right media type and file format

Prepare files for review as well as final delivery.

Guide: /help/project-delivery?guide=file-formats

**Before you begin:** An authorized project uploader.

1. Choose Images for supported photo files, Videos for supported video files, or Documents for the document types offered by the uploader.
2. Review the actual file picker and validation messages for accepted extensions and current limits.
3. Use browser-friendly formats when you need reliable inline preview, and check the finished upload in the client view.
4. For videos, check playback and the generated poster after uploading instead of relying on a filename or file extension alone.
5. If a file cannot be previewed, use a compatible review version or follow the displayed error rather than repeatedly uploading the same unsupported file.

**What happens next:** Your delivery contains files that are appropriate for the intended review and download experience.

**Good to know:** Browser codec support, file size, account storage and the upload entry point can affect availability. A successful upload is not a guarantee that every browser can preview that file.

Related: Add more files to an existing delivery; Troubleshoot a slow image, video or document preview; Download a delivered file.

### Organize delivery files into sections

Create a presentation that your client can navigate easily.

Guide: /help/project-delivery?guide=organize-sections

**Before you begin:** Project owner or the editing access provided by your project view.

1. In a new-project builder, choose the media type for a section and give it a client-friendly name.
2. Select the section’s files and save the section before adding another.
3. For an existing delivery, use Work and the available add-files or section controls to extend the structure.
4. Use Rename section on an existing section heading when its label needs updating.
5. Preview the client portal and confirm that the headings make the delivery easy to understand.

**What happens next:** Files appear under meaningful sections rather than an unexplained collection.

**Good to know:** Section names are visible to clients. Use clear deliverable names rather than internal shorthand.

Related: Add a subsection or folder; Rename or delete a section; Create a direct delivery project.

### Add a subsection or folder

Break a large section into smaller, clearly named groups.

Guide: /help/project-delivery?guide=add-subsection

**Before you begin:** Project owner or the allowed section/task upload access.

1. Find the parent section in Work, or the section being built during project creation.
2. Use the available add-subsection control.
3. Enter the subsection name and choose the appropriate files.
4. Save or upload the subsection and wait for completion.
5. Confirm the files appear under the intended parent rather than creating the same subsection again after a delay.

**What happens next:** The parent section contains an additional organized group of media.

**Good to know:** Managed-task subsections belong to their task workflow until approved work is published to the client.

Related: Organize delivery files into sections; Recover from a failed upload or confirmation; Upload work to an assigned task.

### Rename or delete a section

Keep section headings accurate and understand destructive section actions.

Guide: /help/project-delivery?guide=rename-section

**Before you begin:** The section-management controls must be available to your account.

1. Open Work and find the section heading.
2. Select Rename section, enter the intended label, and save it.
3. Review the updated heading in the client portal.
4. If you intend to delete the section, use the delete control and read the confirmation carefully.
5. Confirm deletion only after checking the files and information affected by the action.

**What happens next:** The section is renamed or the confirmed deletion is applied.

**Good to know:** Deleting a section is not a way to hide it temporarily. Do not delete a populated section just to resolve an upload or loading error.

Related: Organize delivery files into sections; Delete a delivery project deliberately; Recover from a failed upload or confirmation.

### Upload a revised version of a file

Respond to feedback without creating an unrelated new delivery.

Guide: /help/project-delivery?guide=replace-file

**Before you begin:** Owner or the replacement access provided for the delivered file.

1. Open Work and locate the file needing a revision.
2. Read its feedback and review state before choosing the replacement.
3. Select Upload revised version and choose the corrected file.
4. Wait for upload and final registration to finish.
5. Reopen the asset and verify that the latest file is displayed before asking the client to review again.

**What happens next:** The delivered asset points to the revised upload after successful completion.

**Good to know:** Do not assume previous approval still applies to revised work. Check the actual review state after replacement. Replacement availability and allowance can be plan-dependent.

Related: Read client feedback and handle revisions; Recover from a failed upload or confirmation; Approve a file or request a revision.

### Pause an upload and continue safely

Use the upload controls without assuming a tab can preserve every local file.

Guide: /help/project-delivery?guide=upload-pause

**Before you begin:** An upload is in progress and offers a pause/retry control.

1. Keep the uploader open and use Pause uploads where the control is provided.
2. Wait for active transfers to stop before changing the connection or retrying.
3. Use the offered resume or retry action on the same upload flow.
4. Reselect the local file if the interface asks for it and verify its identity.
5. After completion, confirm the file appears in the destination section or task.

**What happens next:** The uploader can reuse valid completed transfer work where supported.

**Good to know:** Pause does not mean delete. A full browser reload or tab close cannot be assumed to preserve the initial project form or local File objects.

Related: Recover from a failed upload or confirmation; Add more files to an existing delivery; Troubleshoot slow uploads.

## Sharing & client access

Share a private portal and manage its presentation.

### Share the client delivery portal

Send the intended review experience rather than the internal project dashboard.

Guide: /help/project-delivery?guide=share-delivery

**Before you begin:** Project owner or the view that exposes approved client-access details.

1. Open the delivery project and select Client access.
2. Use Copy client portal link to copy the public-facing delivery address.
3. Copy the client access code using the provided control.
4. Share the link and code privately with the intended client.
5. Preview the portal yourself and explain that the reviewer may need to enter their name/email and the access code.

**What happens next:** The client can open the intended portal and authenticate for this project.

**Good to know:** An access code is not a team invitation. Do not share your creator login or an internal dashboard URL as client access.

Related: Open and unlock a client delivery; Change the client access code; Understand the client view before and after publication.

### Open and unlock a client delivery

A guide for reviewers receiving a Showwork project link.

Guide: /help/project-delivery?guide=client-unlock

**Before you begin:** The project’s client link and current access code.

1. Open the link supplied by the creator.
2. Enter your name and email when requested so feedback and visits can be associated with your reviewer identity.
3. Enter the project access code at the next gate.
4. After unlocking, use the section navigation and open the file you need to review.
5. If it is a managed project that has not been published yet, expect a progress view instead of the finished files.

**What happens next:** The portal shows the project view available to your authenticated reviewer session.

**Good to know:** Your email identifies feedback; it is not proof of payment or an invitation to the creator’s internal dashboard.

Related: Approve a file or request a revision; Understand the client view before and after publication; Troubleshoot a delivery link or access code.

### Change the client access code

Maintain the code used for the delivery’s client gate.

Guide: /help/project-delivery?guide=change-delivery-code

**Before you begin:** Project owner with the editing controls shown in Client access.

1. Open the project dashboard and choose Client access.
2. Find the access-code field and use its edit control.
3. Enter and save the replacement code using the provided field controls.
4. Copy the updated value and share it privately with intended reviewers.
5. Check the portal login if a client reports that the older code no longer works.

**What happens next:** The saved access code is available for new unlock attempts.

**Good to know:** Do not assume changing a code instantly revokes every already-unlocked browser session. Never use an access-code change as a substitute for checking project membership.

Related: Share the client delivery portal; Open and unlock a client delivery; Invite a collaborator to a delivery project.

### Update the delivery name and presentation

Make the client page feel clear and intentional.

Guide: /help/project-delivery?guide=delivery-presentation

**Before you begin:** Project owner and the editable fields available on that project.

1. Open the project dashboard and locate the editable client name and delivery presentation fields.
2. Use the relevant edit control and save the new value.
3. Review the hero/tagline or branding options available to your project and plan.
4. Open the client portal in a separate tab to check the result on the actual delivery page.
5. Confirm that the file sections still match the names and context your client expects.

**What happens next:** The saved presentation details appear in the delivery experience.

**Good to know:** Presentation options and branding removal depend on your plan. A filename or section label is different from the project’s client-facing title.

Related: Share the client delivery portal; Organize delivery files into sections; Understand Showwork project access versus client payment.

## Feedback & approvals

Review files, handle revisions and read approval progress.

### Approve a file or request a revision

Give the creator an actionable decision on a delivered asset.

Guide: /help/project-delivery?guide=client-review-file

**Before you begin:** An unlocked project reviewer session and a reviewable file.

1. Unlock the client portal and find the image, video or document to review.
2. Inspect the file and use the approval/revision controls displayed with the asset. For video, use the page’s review controls rather than expecting them inside every playback overlay.
3. Choose Approve if the work is ready.
4. If changes are needed, choose the revision action and describe the required change clearly.
5. Submit the decision and check the displayed review state.

**What happens next:** Your approval or revision feedback is recorded for that asset.

**Good to know:** Approval does not pay the creator or automatically unlock downloads. Download release follows the project’s payment state.

Related: Leave feedback at a specific moment in a video; Read client feedback and handle revisions; Confirm payment and release downloads.

### Leave feedback at a specific moment in a video

Make video revisions easier to locate and act on.

Guide: /help/project-delivery?guide=video-feedback

**Before you begin:** An unlocked reviewer session with video commenting available.

1. Open the video and play or seek to the moment you want to discuss.
2. Use Comment at current moment where provided.
3. Enter a clear note describing the issue or desired change.
4. Select Send and check that the timestamped comment appears.
5. Select an existing timestamp to jump back to that moment when reviewing the feedback.

**What happens next:** The comment is associated with a specific playback time.

**Good to know:** Timed comments and the file’s overall approval/revision decision are separate actions. Leave a clear review decision when the creator needs formal sign-off.

Related: Approve a file or request a revision; Read client feedback and handle revisions; Upload a revised version of a file.

### Read client feedback and handle revisions

Use review details to update the right file.

Guide: /help/project-delivery?guide=read-feedback

**Before you begin:** Project owner or the project-review access available to your account.

1. Open the project dashboard and check Overview for revisions needing attention.
2. Go to Work and locate the affected asset.
3. Open its reviews or feedback control to inspect the reviewer’s decision and notes.
4. For timed video feedback, use the timestamp to locate the moment being discussed.
5. Prepare the correction and use Upload revised version when the file needs replacing.
6. Verify the new asset and review state before inviting the client to check it again.

**What happens next:** You respond to the actual feedback instead of creating an unrelated duplicate asset.

Related: Upload a revised version of a file; Read approval progress and delivery health; Approve a file or request a revision.

### Read approval progress and delivery health

Understand what has been reviewed and what still needs attention.

Guide: /help/project-delivery?guide=review-progress

**Before you begin:** Project owner or an authorized project dashboard view.

1. Open Overview and read total files, approved files and revision counts.
2. Inspect the approval percentage and pending-review count.
3. Open Work to identify the files behind any outstanding revisions or pending decisions.
4. Check Delivery & payment separately from the file-review metrics.
5. Follow up with the intended reviewer using the client portal link when a decision is still needed.

**What happens next:** You can distinguish individual file review progress from the overall delivery/payment stage.

**Good to know:** A file count or approval percentage is not a payment receipt. The project-level delivery stage is a separate state.

Related: Understand Delivered, Approved and Paid; Read client feedback and handle revisions; Confirm payment and release downloads.

## Payment & downloads

Confirm payment and release the delivered files.

### Understand Delivered, Approved and Paid

Separate review readiness from download release.

Guide: /help/project-delivery?guide=delivery-stages

**Before you begin:** Project owner for changing the delivery stage; clients can view the stage presented to them.

1. Open the delivery dashboard and inspect Delivery & payment.
2. Use Delivered while the client should review the work; normal download actions remain locked.
3. Use Approved when the delivery has been signed off, while payment is still outstanding.
4. Use Paid only after you have verified receipt of the client’s payment and completed the confirmation.
5. Check the client portal to confirm the intended stage and download availability.

**What happens next:** The delivery stage communicates review/payment status and controls normal client downloads.

**Good to know:** Marking a project Paid is the creator’s confirmation. It is not an automatic bank reconciliation or a payment collection action.

Related: Confirm payment and release downloads; Download a delivered file; Understand Showwork project access versus client payment.

### Confirm payment and release downloads

Make the final download release an explicit, deliberate action.

Guide: /help/project-delivery?guide=confirm-payment

**Before you begin:** Project owner with delivery-status controls.

1. Verify the client payment using your agreed payment method outside the delivery-status control.
2. Open Delivery & payment in the project dashboard.
3. Select the Paid stage.
4. Read the confirmation explaining that delivered-file downloads will be released.
5. Select Confirm payment only when the funds have actually been received.
6. Open the client portal to check that the intended download actions are available.

**What happens next:** Normal client download actions become available for the delivered files.

**Good to know:** Do not mark a project Paid merely to preview the client screen or record verbal payment promises. This control does not itself charge the client.

Related: Understand Delivered, Approved and Paid; Download a delivered file; Understand preview and screenshot protection limits.

### Download a delivered file

Save an individual file after the creator releases the delivery.

Guide: /help/project-delivery?guide=download-files

**Before you begin:** An unlocked reviewer session and a project marked Paid for client downloads.

1. Open the client portal and unlock it with the current access code.
2. Find the delivered file and select its Download action.
3. If downloads are locked, check the payment notice and contact the creator rather than repeatedly retrying.
4. After release, select Download and let the browser’s download manager complete the transfer.
5. If the temporary download request expires or fails, return to the portal and request a fresh download.

**What happens next:** The authorized download starts through the browser.

**Good to know:** Access to an inline preview is different from permission to download an original through the normal delivery controls.

Related: Download a section as a ZIP archive; Confirm payment and release downloads; Troubleshoot a locked or failed download.

### Download a section as a ZIP archive

Collect a manageable group of delivered files in one archive.

Guide: /help/project-delivery?guide=download-section

**Before you begin:** An unlocked reviewer session and released client downloads.

1. Open the paid delivery and find the relevant section.
2. Use the section’s ZIP/download action.
3. Keep the request open while the archive is prepared and streamed.
4. Let the browser save the resulting archive, then extract it on your device.
5. If the selection exceeds the archive limit or takes too long, download individual files instead.

**What happens next:** An authorized archive request delivers the selected section as a ZIP where it fits the limits.

**Good to know:** The current archive route caps requests at 100 files and 1 GiB. Network speed and hosting time limits can also affect completion.

Related: Download a delivered file; Troubleshoot a locked or failed download; Confirm payment and release downloads.

### Understand Showwork project access versus client payment

Keep your subscription or project unlock separate from money owed by the client.

Guide: /help/project-delivery?guide=delivery-billing

**Before you begin:** The creator account responsible for project billing.

1. Read any project-access or allowance notice in your creator dashboard.
2. Use the offered plan or project-access action when you need to restore Showwork functionality.
3. Complete the Showwork payment flow and wait for verified confirmation rather than treating the callback URL alone as proof.
4. Return to the project and check which tools are available.
5. Record the client’s payment separately using Delivery & payment only after you verify receipt.

**What happens next:** You understand which payment changes your Showwork access and which confirmation releases client downloads.

**Good to know:** Paying Showwork for a plan or project does not automatically mean your client has paid you.

Related: Confirm payment and release downloads; Understand Delivered, Approved and Paid; Add more files to an existing delivery.

### Understand preview and screenshot protection limits

Know what download locking can and cannot protect in a browser.

Guide: /help/project-delivery?guide=preview-protection

**Before you begin:** Any creator sharing reviewable work.

1. Treat the client portal’s access gate and normal download lock as access controls, not a guarantee against copying.
2. Assume a person who can view a preview may be able to capture it using screenshots, screen recording or another device.
3. Share only review material you are comfortable exposing before final payment.
4. Use appropriate review-quality or watermarked files when that protection is needed; do not assume the tool automatically creates them for every upload.
5. Confirm payment before releasing normal original-download actions.

**What happens next:** You set realistic expectations when sharing work for review.

**Good to know:** Showwork cannot reliably disable screenshots or screen recording across ordinary browsers. Existing public original URLs also cannot be revoked merely by hiding a download button.

Related: Share the client delivery portal; Confirm payment and release downloads; Download a delivered file.

## Project collaborators

Invite people and understand their access.

### Invite a collaborator to a delivery project

Add a project teammate without sharing your own account.

Guide: /help/project-delivery?guide=delivery-team

**Before you begin:** Project owner with team-management controls.

1. Open the delivery dashboard and choose Team.
2. Search by the teammate’s name or email, or enter a new email address.
3. Select the intended person or email invitation option.

**What happens next:** The person is added or invited to this delivery project.

**Good to know:** Delivery collaborators are not Marketing Workspace roles. Do not assume they receive a Manager, Inbox Agent or internal-review permission from the separate workspace product.

Related: Remove a collaborator or cancel an invitation; Build the managed-project team; Troubleshoot a delivery link or access code.

Keep project membership aligned with the current team.

Guide: /help/project-delivery?guide=remove-delivery-collaborator

**Before you begin:** Project owner with team-management controls.

1. Open Team in the delivery dashboard.
2. Find the active collaborator or pending invitation.
3. Use Remove for the teammate whose project access should end, or Cancel for an invitation that should not be accepted.
4. Check the updated list after the action finishes.
5. Review other projects separately if the same person should also lose access elsewhere.

**What happens next:** The selected membership or invitation is removed from this project.

**Good to know:** Removing project access does not delete the person’s Showwork account or automatically remove memberships in other projects.

## Managed projects

Take work from a brief through tasks and internal review.

### Create a managed project and its brief

Start production before the final files are ready to deliver.

Guide: /help/project-delivery?guide=create-managed

**Before you begin:** A creator account with managed-project access and available allowance.

1. Open the new managed-project flow from your dashboard.
2. Enter a project title and the requested client/project details.
3. Fill in the brief: objective, background, target audience, creative direction, deliverables, brand guidelines and references as needed.
4. Add required formats, platforms, important notes and the deadline where relevant.
5. Submit the project and open The brief to verify what was saved.
6. Continue to The team and The task before releasing finished work.

**What happens next:** The managed project has an internal brief that can guide production.

Related: Update a managed-project brief and attachments; Create and assign a production task; Build the managed-project team; Publish approved managed work to the client.

### Update a managed-project brief and attachments

Keep production requirements and references in one place.

Guide: /help/project-delivery?guide=managed-brief

1. Open the managed project and select The brief.
2. Use its edit control to update the relevant requirements or deadline.
3. Add supporting brief attachments using the available file control.
4. Review the client-visibility option for the brief before saving.
5. Save and check the displayed brief and attachments.

**What happens next:** The team has the latest saved requirements and references.

**Good to know:** Brief attachments are production references, not automatically approved deliverables. Client visibility is a separate choice.

Related: Create a managed project and its brief; Understand the client view before and after publication; Create and assign a production task.

### Build the managed-project team

Give collaborators access before assigning their production work.

**What happens next:** The managed project has the intended production collaborators.

**Good to know:** Only the controls permitted by project ownership and membership are available. Managed-project access is distinct from workspace role customization.

Turn the brief into clear, accountable pieces of work.

Keep in-progress team assets inside their managed-project workflow.

4. Wait for upload and registration to finish.
5. Check the asset’s internal-review state and any feedback before treating it as finished.

**What happens next:** The asset is attached to the task for internal review.

**Good to know:** A task upload is not automatically released as a client-delivery file. It still needs internal approval and publication to the client.

Related: Approve task assets or request internal changes; Publish approved managed work to the client; Recover from a failed upload or confirmation.

### Approve task assets or request internal changes

Review production work before it becomes a client deliverable.

**Before you begin:** Managed-project owner with internal asset-review controls.

1. Open The task and inspect the uploaded asset.
2. Review the actual file against the brief and task requirements.
3. Choose Approve when it is ready, or request changes and enter an actionable note.
4. Submit the review and verify the asset’s state.
5. When approved work is ready to be shared, move to Deliver and publish the approved assets.

**What happens next:** The asset has an internal decision that determines eligibility for client publication.

**Good to know:** Managed-project asset review is different from a client’s approval of the delivered file. Both can occur at different stages.

Related: Upload work to an assigned task; Publish approved managed work to the client; Approve a file or request a revision.

### Publish approved managed work to the client

Release internally approved task files into the client-delivery experience.

Guide: /help/project-delivery?guide=managed-publish

2. Open Deliver and select Publish to client, or Publish new approved work for a project already published.
3. Read the confirmation showing what will become available to the client.
4. Confirm and wait for the result, then check the published-file count.
5. Open the client portal to verify the finished files and their sections.
6. Continue using delivery review/payment controls for client sign-off and download release.

**What happens next:** Eligible approved work is promoted into the linked client delivery.

**Good to know:** Unapproved assets are not made client deliverables by pressing Publish. This action does not publish to social networks and does not confirm client payment.

Related: Approve task assets or request internal changes; Understand the client view before and after publication; Confirm payment and release downloads.

## Activity & project settings

Monitor visits, maintain the project and handle deletion.

### Inspect client visits and delivery activity

See the reviewer identities and visits recorded for the project.

Guide: /help/project-delivery?guide=delivery-activity

**Before you begin:** Project owner with Activity access.

2. Review the recorded viewer names/emails and visit information shown for the delivery.

4. Use the intended client contact rather than assuming every recorded visit is a formal review.
5. Keep viewer email information private when discussing project activity with others.

**What happens next:** You have context about who accessed the project, without treating a visit as approval or payment.

**Good to know:** Activity reflects recorded events, not guaranteed proof that someone watched an entire video, inspected every file or downloaded an original.

### Delete a delivery project deliberately

Remove a project only when you intend to end its delivery access.

Guide: /help/project-delivery?guide=delete-delivery

**Before you begin:** The owner and the project-deletion control available to the account.

1. Open the intended project and verify its identity and client.
2. Keep any files and review records you need before using deletion.
3. Find the project delete action and read the confirmation.
4. Confirm only if the delivery and its associated access should be removed.
5. Check the dashboard afterward rather than trying to fix a deleted link by sharing it again.

**What happens next:** The confirmed deletion is applied to the intended project.

**Good to know:** Deletion is not the same as changing an access code, removing a collaborator or fixing a slow preview. Do not assume it is reversible.

## Troubleshooting

Find the next step when uploading, viewing or downloading fails.

### Recover from a failed upload or confirmation

Check what already succeeded before transferring everything again.

Guide: /help/project-delivery?guide=upload-retry

**Before you begin:** The project’s authorized uploader.

1. Read the upload error and identify whether the problem happened during transfer or final confirmation.
2. Keep the existing uploader open and use its Retry or confirmation-retry control where available.
3. Check the project’s Work section or managed task for files that were already saved.
4. If you have reloaded the page, reopen the existing project rather than assuming creation failed entirely.
5. If the session has expired or the uploader requests a fresh selection, reselect the file and follow the current upload flow.

**What happens next:** You recover the missing transfer or registration without intentionally duplicating successful uploads.

**Good to know:** Resume and registration recovery depend on a valid session. An old expired session cannot be made valid by repeatedly clicking Retry.

Related: Pause an upload and continue safely; Troubleshoot slow uploads; Create a direct delivery project.

### Troubleshoot slow uploads

Distinguish network transfer, processing and final registration.

Guide: /help/project-delivery?guide=slow-upload

**Before you begin:** An authorized uploader.

1. Check the file size, current upload progress and your network connection.
2. Allow the uploader to manage its transfer queue; starting the same batch in multiple tabs can compete for bandwidth.
3. Keep the page open while video previews and final file registration complete.
4. Use Pause uploads if the interface offers it and your connection becomes unstable.
5. If progress stalls or an error appears, use the recovery controls and check saved files before retrying the batch.

**What happens next:** You can identify the slow stage and take a measured next step.

**Good to know:** Large uploads depend on your upload bandwidth and storage/provider response time. The tool does not guarantee a fixed transfer speed.

### Troubleshoot a delivery link or access code

Check the intended project and reviewer gate before retrying.

Guide: /help/project-delivery?guide=access-problems

**Before you begin:** The client link and current code, or owner access to Client access.

1. Confirm you are opening the client portal link rather than an internal dashboard link.
2. Ask the owner to check that the project still exists and copy the current portal link and code from Client access.
3. Complete the name/email step and enter the code exactly as supplied.
4. If the browser already has an unlocked session, refresh the portal and check the project phase rather than expecting the gates every time.
5. For a managed project, ask whether approved work has actually been published to the client.

**What happens next:** You can distinguish an incorrect credential from a deleted project or unpublished managed delivery.

**Good to know:** Never send your creator password, access tokens or unrelated customer records to troubleshoot a client link.

### Troubleshoot a slow image, video or document preview

Check preview availability without re-uploading an entire delivery.

Guide: /help/project-delivery?guide=slow-preview

**Before you begin:** An unlocked client session or authorized project view.

1. Wait for the selected file to load and check your network connection.
2. For video, check both the thumbnail/poster and actual playback; a poster is a separate preview asset.
3. Try a current browser that supports the media’s codec or document format.
4. Ask the creator to verify the saved upload and use a compatible review version if needed.
5. If the file is correctly registered, avoid replacing it solely because an older video has no saved poster.

**What happens next:** You narrow down whether the issue is connection speed, format support, preview generation or an incomplete upload.

**Good to know:** Older videos may lack pre-generated posters. New upload behaviour cannot guarantee that every previously uploaded video already has a thumbnail.

Related: Choose the right media type and file format; Recover from a failed upload or confirmation; Troubleshoot a locked or failed download.

### Troubleshoot a locked or failed download

Check authorization, payment release and archive limits.

Guide: /help/project-delivery?guide=download-problems

**Before you begin:** An unlocked client session or authorized creator account.

1. Read the portal’s payment/download notice before retrying.
2. If downloads are locked, ask the creator to verify payment and confirm the Paid stage.
3. Return to the portal for a fresh download action instead of reusing an old temporary URL.
4. For a failed ZIP, check the 100-file and 1 GiB limits and try individual downloads.
5. Check browser download settings and your connection, then share the visible error with the creator if it persists.

**What happens next:** You can distinguish a payment lock from a temporary link, large archive or transfer failure.

**Good to know:** Repeated download clicks do not bypass access or payment checks. Do not send signed download URLs or access codes to people outside the intended project.
